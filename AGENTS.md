# AGENTS.md — Amilio App (Quasar Vite + Vue 3 + TS)

Repo-specific guidance for OpenCode/agent sessions. Skip generic Vue/TS advice.

## Stack (verified)

- **Quasar Framework v2** on the **Vite CLI** (`@quasar/app-vite` ^2.6) — **not** the legacy Webpack `@quasar/cli`. Doc anchor: https://v2.quasar.dev/quasar-cli-vite/
- **Vue 3.5** + **vue-router 4** (Vue Router v4, Quasar's pinned alias).
- **TypeScript strict** with extra-strict flags (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `allowUnreachableCode: false`) — see `.quasar/tsconfig.json`. Do not loosen without owner approval.
- **ESLint 9 flat config** (`eslint.config.js`) with `vueTsConfigs.recommendedTypeChecked` → type-aware rules require type info to resolve.
- **Prettier** with `singleQuote: true`, `printWidth: 100`.
- **Pinia 3** for cross-component state. Composable domain logic lives in `src/domain/`, `src/repositories/`, `src/services/`.
- **vue-i18n 11** (Composition API only, `legacy: false`). 8 shipped locales: en, es, pt-BR, de, fr, ja, ko, it.
- **`@capacitor-community/sqlite` ^8** for native Android persistence. See §SQLite below.
- **Vitest 4 + @vue/test-utils 2 + jsdom 27** for unit tests.
- **pnpm** workspace (see `pnpm-workspace.yaml` — `shamefullyHoist: true`, `onlyBuiltDependencies: @parcel/watcher, esbuild`).

## Commands

| Goal                                          | Command                                                  |
| --------------------------------------------- | -------------------------------------------------------- |
| Install deps (regenerates `.quasar/`)         | `pnpm install` (runs `quasar prepare` via `postinstall`) |
| Dev server (auto-opens browser)               | `pnpm dev` → `quasar dev`                                |
| Production build                              | `pnpm build` → `quasar build`                            |
| Lint (matches editor + `vite-plugin-checker`) | `pnpm lint`                                              |
| Format                                        | `pnpm format`                                            |
| Type check                                    | `pnpm typecheck` (alias for `vue-tsc --noEmit`)          |
| Unit tests (single run)                       | `pnpm test` (`vitest run`)                               |
| Unit tests (watch)                            | `pnpm test:watch`                                        |
| Capacitor sync (Android)                      | `pnpm cap:sync` (builds then runs `cap sync android`)    |

`pnpm dev` runs in the browser. SQLite calls fall back to an in-memory dev stub with a one-time console warning; the dev stub is **only** useful for visual smoke testing of the onboarding flow. Real persistence only happens in the Android build.

## SQLite / Android

- The native SQLite engine is reached only inside the Capacitor Android build
  via `@capacitor-community/sqlite` ^8.1.1. Peer: `@capacitor/core >=8.0.0`.
- Browser `quasar dev` falls back to `DevStubConnection` in
  `src/database/connection.ts`. The stub is **deliberately** minimal — it is
  only there so visual flow testing works.
- The Application ID is `br.com.amilo` (declared in
  `src-capacitor/capacitor.config.json`). It must NOT be changed without owner
  approval — it is registered in the Google Play Store.
- The Android platform is scaffolded via `npx cap add android` and must be kept
  in sync with the web build via `pnpm cap:sync`.

## Path aliases (already configured in `.quasar/tsconfig.json`)

Use them in imports — don't build relative paths:

- `components/*`, `layouts/*`, `pages/*`, `stores/*`, `boot/*`, `assets/*`
- `src/*`, `app/*`
- `#q-app`, `#q-app/wrappers` (Quasar wrappers like `defineRouter`, `defineConfig`)

## Routing (`src/router/`)

- `routes.ts` declares routes; `index.ts` uses the `#q-app/wrappers` `defineRouter` helper.
- The `beforeEach` guard in `index.ts` checks `user_preferences.onboarding_completed_at`.
  Routes with `meta.requiresOnboarding === true` redirect to `/onboarding` when missing.
- **History mode is controlled by `quasar.config.ts > build.vueRouterMode`** (currently `'hash'`). To switch to history mode, edit `quasar.config.ts` — the router reads `process.env.VUE_ROUTER_MODE` injected by Quasar at build/dev time. Do **not** try to flip mode via env vars alone.
- `publicPath` likewise lives in `quasar.config.ts > build`.

## Auto-imports

Components, directives, and Quasar plugins in `src/components/`, `src/layouts/`, `src/pages/` are **auto-imported**. No manual `import` is required for them in templates. Named imports in `<script setup>` are fine.

## Lint gotchas

- Lint glob (`package.json`): `src*/**/*.{ts,js,cjs,mjs,vue}` — covers `src/`, `src-pwa/`, `src-cordova/`, `src-capacitor/`, etc.
- `vueTsConfigs.recommendedTypeChecked` runs type-aware rules. If `vue-tsc` reports errors, expect `pnpm lint` to fail on the same.
- The dev server wires the **exact same lint command** via `vite-plugin-checker` → errors show in the browser overlay.
- `no-debugger` is `off` in dev, `error` in production builds.
- `prefer-promise-reject-errors: off` — non-default.

## Modes NOT currently in use

`quasar.config.ts` defines SSR/PWA/Cordova/Capacitor/Electron/BEX blocks but only the **SPA** parts (`boot`, `css`, `extras`, `build`, `devServer`, `framework`) are active. Don't enable SSR/PWA etc. without owner sign-off — defaults and `pwa: false` are deliberate.

## Conventions / gotchas

- Node engine: `^28 || ^26 || ^24 || ^22.12`. Use a supported LTS; older Node 22 (<22.12) won't run.
- After dependency changes, `pnpm install` regenerates `.quasar/tsconfig.json` and `.quasar/quasar.d.ts`. If path aliases seem wrong, re-run `pnpm install` (or `npx quasar prepare`) instead of editing `.quasar/`.
- `pnpm` only allows build scripts for `@parcel/watcher` and `esbuild`. Other packages will need explicit approval via `pnpm-workspace.yaml > onlyBuiltDependencies` if they ship install hooks.
- `.env.local*` is gitignored. The only typed env vars are `NODE_ENV`, `VUE_ROUTER_MODE`, `VUE_ROUTER_BASE` (see `src/env.d.ts`).
- Editor expectations (`.vscode/settings.json`): format-on-save via Prettier + `source.fixAll.eslint` on save. Recommended extensions: `vue.volar` (not Vetur), `dbaeumer.vscode-eslint`, `esbenh.prettier-vscode`.

## Where to look first when something's unclear

1. `quasar.config.ts` — build/dev/framework knobs
2. `package.json` scripts + lockfile
3. `eslint.config.js` for lint behavior
4. `.quasar/tsconfig.json` for path aliases / strict TS flags
5. `src/router/routes.ts` and `src/layouts/` for app shell
6. `src/domain/` for business rules (age, metabolism, conversions, locale)

Official Quasar Vite docs: https://v2.quasar.dev/quasar-cli-vite/ — defer to these over blog posts.
